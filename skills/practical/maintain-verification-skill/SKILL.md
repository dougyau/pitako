# Maintain a verification skill

Upkeep for a skill generated by `create-verification-skill`, or any project-local verification skill with a feature map.

This is a single-agent skill. Do not spawn one reader per feature.

## Outcomes

Pick one, and say which:

- **clean** — every feature got source and live coverage; nothing worth shipping
- **changed** — proven doc, harness, or map corrections
- **blocked** — coverage could not finish, or a proven fix could not ship safely

## Edit scope

Only edit the verification skill's directory. Never edit product code during a run. Behavior the map describes that the app no longer does is either doc drift (fix the map) or a product regression (report it).

## Pass

1. **Locate the target.** Usually `.pi/skills/verify-*/`. None → stop and point at `create-verification-skill`.
2. **Index hygiene.** Fix missing, extra, or dead feature-map entries.
3. **Source pass.** For each feature, explain how it works from source (CodeGraph / LSP / targeted reads). Flag likely doc drift with citations.
4. **Live pass.** Follow the verification skill's own launch model. Doctor before driving. Exercise every feature at least once when that is cheap. Evidence survives cleanup.
5. **Triage.** Wrong description → fix the map. Harness cannot drive working behavior → fix the harness. App is broken → report it, keep it out of the doc PR.
6. **Stop.** Do not polish product code. Report coverage honestly.
